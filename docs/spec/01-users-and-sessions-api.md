# 01. Users and sessions API (Part 0)

A Node.js service exposing REST APIs for the User and Session domains. All paths are under `/api`.
In Part 0 the API has no authentication; [02 Authentication](02-authentication.md) protects it.
Errors follow [05 Errors](05-errors.md).

## User

| Field         | Type                     | Notes                                     |
| ------------- | ------------------------ | ----------------------------------------- |
| `id`          | UUID                     | generated by the server                   |
| `firstName`   | string, 1 to 100 chars   | trimmed; must not be blank                |
| `lastName`    | string, 1 to 100 chars   | trimmed; must not be blank                |
| `status`      | `active` \| `inactive`   | default `active`                          |
| `loginsCount` | integer ≥ 0              | read-only; starts at 0                    |
| `createdAt`   | ISO 8601 timestamp (UTC) | read-only; set once on creation           |
| `updatedAt`   | ISO 8601 timestamp (UTC) | read-only; equals `createdAt` on creation |

Part 1 adds `email` (see [02](02-authentication.md)).

### Create a user

- **USR-01** `POST /api/users` with `firstName`, `lastName` and optional `status` creates a user and
  returns `201` with the user. `loginsCount` is 0 and `updatedAt` equals `createdAt`.
- **USR-02** Unknown fields, including read-only ones (`id`, `loginsCount`, `createdAt`,
  `updatedAt`), are rejected with `400 VALIDATION_FAILED`. Invalid values are rejected the same way,
  with one entry per invalid field.

### List users

- **USR-03** `GET /api/users?page=&pageSize=` returns `200` with
  `{ items, page, pageSize, totalItems, totalPages }`.
- **USR-04** Defaults: `page=1`, `pageSize=6`. `page` is an integer ≥ 1; `pageSize` an integer from
  1 to 100. Other values are rejected with `400 VALIDATION_FAILED`.
- **USR-05** Users are ordered by `createdAt` descending, then `id` descending, so pages are stable.
- **USR-06** A page beyond the last returns `200` with empty `items` and the correct totals.
  `totalPages` is 0 when there are no users.

### Update a user's profile

- **USR-07** `PATCH /api/users/:id` with `firstName` and/or `lastName` (at least one) updates the
  profile and returns `200` with the user.
- **USR-08** Only `firstName` and `lastName` are accepted. Any other field, including `status`,
  `createdAt` and `id`, is rejected with `400 VALIDATION_FAILED`. Status has its own endpoint
  (USR-10), so a single request can never change both profile and status.
- **USR-09** If the user is `inactive`, the request is rejected with `409 USER_NAME_LOCKED` and
  nothing changes.

  > Given an inactive user, when their first name is updated, then the API responds 409
  > `USER_NAME_LOCKED` and the stored user is unchanged.

### Change a user's status

- **USR-10** `PUT /api/users/:id/status` with `{ "status": "active" | "inactive" }` sets the status
  and returns `200` with the user. Setting the current status again succeeds.
- **USR-11** Deactivating a user terminates all of their active sessions in the same transaction.

### Update time

- **USR-12** Every successful update (profile, status, or the logins counter, see SES-03) sets
  `updatedAt` to the current time. `createdAt` never changes.

### Remove a user

- **USR-13** `DELETE /api/users/:id` deletes the user and all of their sessions and returns `204`.

### Common

- **USR-14** Operations on a user id that does not exist return `404 USER_NOT_FOUND`. A malformed id
  returns `400 VALIDATION_FAILED`.

## Session

| Field          | Type                       | Notes                                                    |
| -------------- | -------------------------- | -------------------------------------------------------- |
| `id`           | UUID                       | generated by the server; also the session credential     |
| `userId`       | UUID                       | owner                                                    |
| `createdAt`    | ISO 8601 timestamp (UTC)   | set on creation                                          |
| `terminatedAt` | ISO 8601 timestamp or null | null while the session has not been terminated           |
| `expiresAt`    | ISO 8601 timestamp (UTC)   | `createdAt` + session TTL (default 7 days, configurable) |

A session is **active** when `terminatedAt` is null and `expiresAt` is in the future.

### Create a session

- **SES-01** `POST /api/sessions` with `{ userId }` creates a session for an active user and returns
  `201` with the session.
- **SES-02** If the user is `inactive`, it is rejected with `403 USER_INACTIVE` and no session is
  created. An unknown user returns `404 USER_NOT_FOUND`.
- **SES-03** Creating a session increments the user's `loginsCount` by 1 atomically (concurrent
  sign-ins never lose an increment) and updates `updatedAt` (USR-12).

Part 1 removes this endpoint: once authentication exists, sessions are created only by sign-up and
sign-in (AUTH-01, AUTH-03).

### Terminate a session

- **SES-04** `DELETE /api/sessions/:id` sets `terminatedAt` to the current time and returns `204`.
  The record is kept.
- **SES-05** Terminating an already terminated or expired session returns `204` and does not change
  `terminatedAt` (idempotent).
- **SES-06** An unknown session id returns `404 SESSION_NOT_FOUND`.

## Health

- **HLT-01** `GET /api/health/live` returns `200` while the process runs. `GET /api/health/ready`
  returns `200` when the database is reachable, otherwise `503`.

## API documentation

- **API-01** The OpenAPI document is generated from the same schemas that validate requests and is
  served with an interactive UI at `/api/docs`.
